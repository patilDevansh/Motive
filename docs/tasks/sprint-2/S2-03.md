# Validate and persist store catalog CSV imports

## Description
Let store owners import a catalog used by product browsing, analytics and recommendations. This slice supplies transactional SQLite persistence and a local FastAPI import service. Event imports, owner authentication, UI and recommendation changes are separate tasks. The service is a local development interface, not a publicly deployable authenticated service.

## Specs
- `src/catalog_store.py`: `CatalogStore(path).import_catalog(store_id, csv_text)` returns `{inserted, updated}`. `list_products(store_id, limit=50, offset=0)` returns `{items, total, limit, offset}`, sorted by product_id. Store IDs must be nonempty after trimming; limit is 1–100 and offset nonnegative.
- CSV header exactly: `product_id,name,category,price,currency,available,url` in any order. UTF-8 BOM is accepted. All fields required except category and url may be empty. IDs/name cannot be blank. Price is a finite nonnegative decimal stored as a string; currency is three uppercase ASCII letters; available is true/false (case-insensitive); nonempty URL must be HTTP(S) with a host.
- Duplicate product IDs within a file, missing/extra headers, malformed CSV, wrong field counts, and invalid field values reject the entire file. `ImportValidationError.errors` contains `{line,field,message}` entries. Empty catalogs (header only) are valid no-ops.
- Existing `(store_id,product_id)` entries update; all accepted rows commit in one transaction. Reads never include other stores. Opening another CatalogStore on the same database preserves data.
- `api/store.py` exposes `create_app(db_path)` and `app`; POST `/stores/{store_id}/catalog/import` with raw text/csv body returns counts; GET `/stores/{store_id}/products?limit=50&offset=0` returns the page. Validation returns HTTP 400 `{errors:[...]}`; invalid query bounds return 422. `MOTIVE_STORE_DB` sets default database path. Run on localhost only until owner authentication is implemented.

## Requirements
Use parameterized sqlite3 operations and stdlib CSV/decimal validation; no model artifacts or changes to the recommendation engine. Preserve product-statistics code/tests. Close each database connection. FastAPI dependencies go in requirements-imports.txt. Tests use temporary databases and never the production store.

## Acceptance criteria
1. A valid catalog imports, survives reopening, and returns the specified JSON fields.
2. Invalid rows report their line and field and leave all existing data unchanged, including earlier valid rows in the same file.
3. Reimporting a product ID updates that store's row without adding a duplicate; duplicate IDs within a file reject it.
4. Identical product IDs in separate stores never leak or overwrite another store's data.
5. Pagination is deterministic, has no duplicate/missing items, and rejects invalid limits/offsets.
6. The HTTP endpoints return documented success/error responses; empty and BOM inputs follow the contract.

## Tests
`tests/test_S2_03_catalog.py`: temporary SQLite fixtures; pytest parameter IDs start `S2-03`. Tests cover restart/read values (1), parameterized invalid cells plus rollback (2), upserts and in-file duplicates (3), store isolation (4), pagination/bounds (5), HTTP success/error and BOM/header-only behavior (6).
