# Show import results after a store owner uploads a catalog CSV

## Description
A store owner who wants Motive to recommend from their own products first has to
upload a product catalog. This task adds the catalog upload screen: a downloadable
CSV template, a file picker, an upload button with a pending state, and a results
summary that shows either the import counts or the rows that failed. It serves the
Sprint 2 extended goal ("an owner can upload store data, inspect product
performance, and request recommendations from that same imported dataset").

Out of scope: server-side CSV validation and storage (S2-03), event uploads
(S2-06), the catalog browser that the "View catalog" link opens (S2-09), and
authentication or choosing between stores.

## Specs
- A new **Import** section (`id="import"`) is added to the page and to the header
  navigation. It contains the `CatalogUpload` component
  (`frontend/src/components/CatalogUpload.jsx`, wrapper `id="catalog-upload"`).
- **Template.** A "Download CSV template" link points to
  `/templates/catalog_template.csv` with the `download` attribute. The file's
  header row is exactly
  `product_id,name,category,price,currency,available,url`.
- **Choosing a file.** The file input (label "Catalog CSV file") accepts `.csv`.
  If the chosen file's name does not end in `.csv` (case-insensitive), the screen
  shows "Choose a .csv file." If the file is empty (0 bytes), it shows "This file
  is empty." In both cases the upload service is not called.
- **Upload.** Pressing "Upload catalog" calls
  `uploadCatalog(storeId, file, signal)` in `frontend/src/services/importApi.js`,
  which sends `POST /stores/{storeId}/catalog/import` as `multipart/form-data`
  with the file in the field `file`. `storeId` defaults to `"demo"`.
- **Pending.** While the request is in flight, the button is disabled and reads
  "Uploading…", the file input is disabled, and further submits do not send
  another request.
- **Success** (HTTP 2xx with `{ "imported": N, "updated": M }`). A status message
  reads "Imported N new products and updated M existing products." (singular
  "product" when the count is 1), followed by a "View catalog" link to `#catalog`.
- **Row errors** (HTTP 400, 409 or 422 with `errors: [{ line, field, message }]`,
  either at the top level or under `detail`). An alert reads
  "K rows have problems. Nothing was imported." and lists every error as
  "Line L · F: message". At most 20 rows are listed, followed by "…and X more."
  The owner can choose a corrected file and upload again.
- **Other failures** (network error, other HTTP status, or a 2xx body without
  numeric counts). An alert shows the reason and a "Try again" button that
  resends the same file. A successful retry replaces the alert with the success
  message.

## Requirements
- The response contract above is an assumption until S2-03 is merged. All request
  and response handling lives in `frontend/src/services/importApi.js`, so only that
  file changes if the contract changes. Tests use fixtures and never call a real
  server.
- The upload flow (validation, pending guard, retry, abort on unmount) lives in a
  reusable hook, `frontend/src/hooks/useCsvUpload.js`, so S2-06 can reuse it
  without changing it.
- No new runtime dependencies. Dev-only test dependencies are added: `vitest`,
  `jsdom`, `@testing-library/react`, `@testing-library/dom`,
  `@testing-library/user-event`, `@testing-library/jest-dom`, plus an
  `npm test` script.
- Styles use the existing design tokens in `App.css` and live in
  `frontend/src/components/import.css`. Existing sections, styles and tests keep
  working, and `npm run build` still succeeds.
- Status and errors are announced to screen readers (`role="status"` for success
  and pending, `role="alert"` for failures).

## Acceptance criteria
1. The "Download CSV template" link points to `/templates/catalog_template.csv`, has the `download` attribute, and that file's header row is exactly `product_id,name,category,price,currency,available,url`.
2. Choosing a file that is not `.csv`, or an empty file, shows the matching message and the upload service is not called.
3. While an upload is pending, the button is disabled and reads "Uploading…", and submitting twice sends only one request.
4. A successful upload shows "Imported N new products and updated M existing products." with N and M from the response, and a "View catalog" link to `#catalog`.
5. A response with row errors states that nothing was imported and lists each error with its line, field and message.
6. After a network or server failure, "Try again" resends the same file, and a successful retry shows the success message instead of the error.
7. `uploadCatalog` sends the file in the multipart field `file` to `POST /stores/{storeId}/catalog/import`, and turns a 400, 409 or 422 response with `errors` (top level or under `detail`) into row errors.
