# Return per-product view, cart and purchase counts for a store

## Description
Serves the Product-numbers story (store owners see how each product is performing). In Sprint 1 the counts were built offline from the Retailrocket CSV. This task adds an endpoint to the store import service (`api/store.py`, from S2-03 and S2-04). The endpoint counts the views, carts and purchases that a store has imported for each catalog product, so the product-performance dashboard (S2-10) can show them. Products come back one page at a time, the same way as the existing `GET /stores/{store_id}/products`.

Out of scope: importing CSV files (S2-03, S2-04), filtering by date (S2-08), the dashboard screen (S2-10), conversion rates, and owner authentication.

## Specs
- New function `get_product_stats(db_path, store_id, limit=50, offset=0)` in `src/product_event_stats.py`. It returns:
  ```json
  {
    "items": [
      {"product_id": "p1", "name": "Blue Mug", "category": "kitchen",
       "views": 3, "carts": 1, "purchases": 1}
    ],
    "total": 3,
    "limit": 50,
    "offset": 0
  }
  ```
- New endpoint `GET /stores/{store_id}/products/stats?limit=50&offset=0` in `api/store.py`. It returns the function's result with HTTP 200.
- `total` is the number of products in the store's catalog.
- Items are sorted by `product_id`, the same order as `GET /stores/{store_id}/products`.
- `views`, `carts` and `purchases` count that product's stored events whose `event` is `view`, `cart` and `purchase`.
- Edge cases:
  - A catalog product with no events is listed, with all three counts 0.
  - Importing the same events file again does not change any count.
  - Products and events from other stores are never listed or counted, even when another store uses the same `product_id`.
  - An `offset` past the last product returns `"items": []` with the correct `total`.
  - A store with no products, or a brand new database, returns `"items": []` and `"total": 0`.
  - `limit` outside 1–100, or `offset` below 0, returns HTTP 422 (FastAPI query validation), the same as `GET /stores/{store_id}/products`.

## Requirements
- Read-only: only `SELECT` queries; no rows are added, changed or deleted.
- Read the `products` and `events` tables exactly as S2-03 and S2-04 create them. Do not change their schema or the import code.
- Use parameterized SQLite queries (`?`) with Python's built-in `sqlite3`. No new libraries.
- The existing S2-03, S2-04 and Sprint 1 tests must keep passing.

## Acceptance criteria
1. For a known imported fixture, each product's `views`, `carts` and `purchases` match the fixture exactly, and each item has the product's `name` and `category`.
2. A catalog product with no events is listed with `views`, `carts` and `purchases` all 0.
3. Importing the same events file a second time leaves every count unchanged.
4. Products and events from another store are not listed or counted.
5. Items are sorted by `product_id`, `total` equals the number of catalog products in the store, and paging through with `limit` and `offset` returns each product exactly once.
6. An `offset` past the last product returns an empty `items` list with the correct `total`, and an unknown store returns `total` 0.
7. `GET /stores/{store_id}/products/stats` returns HTTP 200 with the JSON shape in Specs.
8. `limit=0`, `limit=101` and `offset=-1` each return HTTP 422.

## Tests
File: `tests/test_S2_07_product_stats.py`
Setup for all: a temporary SQLite file (pytest `tmp_path`) filled with `EventStore` from S2-04. Store `store-a` imports a catalog with `p1` (Blue Mug, kitchen), `p2` (Red Lamp, home) and `p3` (Green Pen, office). It imports events giving `p1` 3 views, 1 cart and 1 purchase, and `p2` 1 view and 2 carts. `p3` has no events. Store `store-b` imports its own `p1` with 5 views, and a product `p9`. API tests use FastAPI's `TestClient` with `create_app(<tmp database path>)`.

- `test_S2_07_counts_match_fixture`: calls `get_product_stats` for `store-a` and asserts the full items for `p1` and `p2`. Covers 1.
- `test_S2_07_product_with_no_events_shows_zeros`: asserts `p3` is listed with 0, 0, 0. Covers 2.
- `test_S2_07_reimport_does_not_inflate`: imports the same `store-a` events file again, then asserts the counts for `p1` and `p2` are unchanged. Covers 3.
- `test_S2_07_other_store_excluded`: asserts `store-a` lists only `p1`, `p2` and `p3`, and that `p1` has 3 views, not 8. Covers 4.
- `test_S2_07_pages_cover_every_product_once`: reads `store-a` with `limit=2` at `offset=0` and `offset=2`, and asserts the ids are `["p1", "p2"]` then `["p3"]`, with `total` 3 both times. Covers 5.
- `test_S2_07_empty_pages_and_unknown_store`: asserts `offset=3` gives `items == []` and `total == 3`, and that store `nope` gives `items == []` and `total == 0`. Covers 6.
- `test_S2_07_api_returns_json`: calls `GET /stores/store-a/products/stats`, asserts status 200 and the full body for the first page. It also calls the endpoint on a brand new database and asserts `total` 0. Covers 7 and 6.
- `test_S2_07_api_rejects_bad_paging`: calls the endpoint with `limit=0`, `limit=101` and `offset=-1`, and asserts status 422 each time. Covers 8.
