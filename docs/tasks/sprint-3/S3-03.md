# Accept CSV file uploads on the catalog and event import endpoints

## Description
Serves the Store-data-import story (a store owner uploads their own catalog and shopper events). The import endpoints from S2-03 and S2-04 only read a raw `text/csv` request body, but a browser file picker sends `multipart/form-data`, which is what the upload screens (S2-05 catalog upload, the event upload screen) are specified to send. This task lets both import endpoints accept a file uploaded in a multipart form, so the upload screens can call the real service.

Out of scope: the upload screens themselves, changing the CSV validation rules or the response bodies of S2-03 and S2-04, owner authentication (S3-04), streaming or background imports, and serving the store endpoints from the same origin as the React app.

## Specs
- `POST /stores/{store_id}/catalog/import` and `POST /stores/{store_id}/events/import` in `api/store.py` accept two request formats:
  - `Content-Type: text/csv` with the CSV as the raw body. Behavior is unchanged from S2-03 and S2-04.
  - `Content-Type: multipart/form-data` with the CSV in a file part named `file`.
- A multipart upload is validated and stored exactly like the same CSV text sent as `text/csv`. The success bodies are unchanged: `{"inserted": N, "updated": M}` for the catalog and `{"inserted": N, "skipped": M}` for events. Row validation errors are unchanged: HTTP 400 `{"errors": [{"line", "field", "message"}]}` and nothing is stored.
- A UTF-8 byte order mark at the start of an uploaded file is accepted, as in S2-03.
- Upload errors return `{"errors": [{"line": 0, "field": "file", "message": "..."}]}` and store nothing:
  - Multipart request with no part named `file`, or with `file` sent as a plain text field instead of a file: HTTP 400, message `Upload the CSV in a file field named file`.
  - File or raw body that is not valid UTF-8: HTTP 400, message `File must be UTF-8 text`.
  - File or raw body larger than the size limit: HTTP 413, message `File is larger than 5 MB`.
  - Any other content type (for example `application/json`): HTTP 415, message `Send text/csv or multipart/form-data`.
- The size limit is `MAX_IMPORT_BYTES = 5 * 1024 * 1024` in `api/store.py`. `create_app(db_path, max_import_bytes=MAX_IMPORT_BYTES)` takes the limit as an optional argument so tests can use a small one. A body of exactly the limit is accepted. The message names the limit in use: `5 MB` for the default, and a limit below 1 MB is written in bytes (for example `File is larger than 200 bytes`).
- A zero-byte uploaded file is passed to the existing validation and gets its existing HTTP 400 header error.
- Extra form fields besides `file` are ignored. The uploaded file's name and its part content type are not checked.

## Requirements
- Do not change `src/catalog_store.py` or `src/event_store.py`. The request format is handled in `api/store.py` only.
- The S2-03, S2-04, S2-07 and S2-08 tests must pass without changes.
- Add `python-multipart`, pinned, to `requirements-imports.txt`. No other new libraries.
- Never write the uploaded file to a path chosen by the client. Do not use the uploaded filename.
- Tests use temporary databases and FastAPI's `TestClient`. They never call a real server.
- Document the multipart format in `docs/STORE_IMPORTS.md`.

## Acceptance criteria
1. A valid catalog CSV uploaded as multipart field `file` returns HTTP 200 with the same `inserted` and `updated` counts as the raw `text/csv` request, and the products are returned by `GET /stores/{store_id}/products`.
2. A valid events CSV uploaded as multipart field `file` returns HTTP 200 with `inserted` and `skipped` counts, and the events are returned by `GET /stores/{store_id}/events`.
3. A multipart upload with an invalid row returns HTTP 400 with that row's `line` and `field`, and no row from the file is stored.
4. A multipart request without a file part named `file` returns HTTP 400 with field `file` and message `Upload the CSV in a file field named file`.
5. A file that is not valid UTF-8 returns HTTP 400 with field `file` and message `File must be UTF-8 text`, for both multipart and raw requests, and nothing is stored.
6. A file one byte over the size limit returns HTTP 413 with field `file` and a message naming the limit, and a file of exactly the limit is not rejected for size.
7. A request with another content type returns HTTP 415 with field `file` and message `Send text/csv or multipart/form-data`.
8. A file that starts with a UTF-8 byte order mark imports successfully through multipart.

## Tests
File: `tests/test_S3_03_file_upload.py`. Test names start with `test_S3_03_`. Each test builds `TestClient(create_app(<tmp database path>))`.

- `test_S3_03_catalog_multipart_matches_raw`: uploads the same catalog to store `a` as multipart and to store `b` as raw `text/csv`; asserts both return 200 with equal counts and that `GET /stores/a/products` lists the rows. Covers 1.
- `test_S3_03_events_multipart_import`: imports a catalog, uploads events as multipart, asserts the counts and `GET /stores/a/events`; uploads the same file again and asserts every row is skipped. Covers 2.
- `test_S3_03_multipart_invalid_row_stores_nothing`: uploads a catalog whose second data row has a bad price and an events file with an unknown product; asserts 400, the line and field, and that nothing was stored. Covers 3.
- `test_S3_03_missing_file_field`: sends multipart with the file under another field name, and with `file` as a text field; asserts 400 and the exact error body. Covers 4.
- `test_S3_03_rejects_non_utf8`: sends bytes that are not UTF-8 as multipart and as raw; asserts 400, the exact error body and an empty catalog. Covers 5.
- `test_S3_03_size_limit`: with `max_import_bytes=200`, a 201-byte upload returns 413 with the exact error body for multipart and raw, and a valid catalog padded to exactly 200 bytes returns 200. Covers 6.
- `test_S3_03_default_limit_message`: with the default limit, a file of 5 MB plus one byte returns 413 and the message `File is larger than 5 MB`. Covers 6.
- `test_S3_03_rejects_other_content_types`: posts `application/json` and a URL-encoded form to both endpoints; asserts 415 and the exact error body. Covers 7.
- `test_S3_03_multipart_bom`: uploads a catalog that starts with a byte order mark; asserts 200 and one inserted product. Covers 8.
